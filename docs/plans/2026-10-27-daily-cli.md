# Daily CLI, controller discovery, and doctor

Date: 2026-10-27. Baseline: `082bdf7`.

## Problem

Every useful action except a handful of status commands needs the TUI, and the TUI finds the controller only when it sits at the old Clash Verge Rev path `/tmp/verge/verge-mihomo.sock`. Current Clash Verge Rev in service mode starts the core with `-ext-ctl-unix /var/run/clash-verge-service/users/<uid>/verge-mihomo.sock`, while its generated `clash-verge.yaml` still names a socket under `$TMPDIR`. On such a machine `clash-vr-tui` with no flags connects to nothing. There is also no way to watch core logs from a shell, and no single command that tells the user what is wrong with their setup.

## Goals

1. With no flags, find the running controller on the common layouts (Verge service mode, Verge user mode, plain mihomo, ClashX Meta style TCP controllers) and say how it was found.
2. Every page action of the TUI is also a subcommand, so SSH and scripts never need the TUI.
3. `logs` streams core logs live at a chosen level.
4. `doctor` checks the whole path from controller to internet, explains each problem with a next step, and can save a bundle for later analysis.

Non-goals: editing Clash Verge Rev profiles, shell completion, a daemon mode.

## Command surface

Commands stay flat (`clash-vr-tui <command>`); aliases in parentheses.

| Group | Command | Notes |
| --- | --- | --- |
| Find | `discover` (`list-socket`, `sockets`) | Lists candidate controllers with source, reachability, version; marks the one auto-detect would use. Does not need a working controller. |
| Inspect | `status`, `proxies` (`groups`), `nodes <group>`, `conns` (`connections`) | Existing. `status` adds the endpoint and how it was chosen. |
| Inspect | `rules [--grep S]` | Routing rules, filtered by substring. |
| Inspect | `providers` | Proxy and rule providers: type, node count, last update, subscription usage and expiry. |
| Inspect | `config` | Runtime config (ports, mode, TUN, LAN, log level). |
| Live | `logs` (`log`) `[--level L] [--grep S] [--for DUR]` | Streams `WS /logs`. Levels: debug, info, warning, error. Reconnects after a core restart. |
| Control | `switch`, `test`, `mode`, `restart` | Existing. |
| Control | `unpin <group>` | Clears a URLTest/Fallback fixed node. |
| Control | `close <id>... \| --all \| --host S` | Closes connections. |
| Control | `config set tun\|lan on\|off`, `config set log-level L` | Explicit CLI intent, so no prompt. Reads the value back and fails if the core did not keep it. |
| Control | `providers update [name...]` | Updates proxy providers (all when no name). |
| Control | `flush dns\|fakeip` | Clears core caches. |
| Diagnose | `doctor` (`autodebug`) `[--logs DUR] [--level L] [--probe] [--out DIR]` | See below. |

Output conventions: aligned plain text by default, `--json` everywhere data is printed, NDJSON for `logs --json`. Color only when stdout is a terminal and `NO_COLOR` is unset. Controller text always passes through `styles.SafeText`. Exit codes: 0 success, 1 runtime failure (doctor: any `fail` finding), 2 usage error. Ctrl+C on a streaming command exits 0.

## Discovery

Package `internal/discover`, no dependency on `internal/config`. A candidate is a socket path, a Windows pipe, or a TCP address, plus an optional secret and the list of sources that named it. Sources in priority order:

1. Running processes (`ps -axww -o command=` on Unix): mihomo or clash processes with `-ext-ctl-unix`, `-ext-ctl`, `-ext-ctl-pipe`, `-secret`, and the config named by `-f` or `-d`.
2. Config files: the Clash Verge Rev app directory (`clash-verge.yaml`, `config.yaml`) and the usual mihomo, clash, and clash-meta locations, reading `external-controller-unix`, `external-controller`, `external-controller-pipe`, and `secret`. A wildcard or `0.0.0.0` host becomes `127.0.0.1`.
3. Known paths: `/var/run/clash-verge-service/users/<uid>/verge-mihomo.sock`, `/tmp/verge/verge-mihomo.sock`, `$TMPDIR/verge-mihomo.sock`; on Windows the `verge-mihomo` and `mihomo` pipes.

Candidates are deduplicated by address, socket files that do not exist are dropped, and the rest are probed in parallel with `GET /version` under a one-second timeout. Each gets a state: `ok` (with version), `unauthorized`, `refused`, `permission denied`, or `timeout`. `discover.Best` returns the first `ok` candidate in priority order.

Resolution: flags > env > config file > auto-detect > the old default path. Only the last two tiers are new; an explicit endpoint is never second-guessed. `config.Resolved` gains `Source`, a short phrase such as `flag`, `env`, `config file`, `auto-detected from process verge-mihomo -ext-ctl-unix`, or `default path`. When nothing answers, errors suggest `clash-vr-tui discover`. Auto-detect is a package variable so tests never touch the real machine.

## Doctor

Package `internal/doctor` gathers data through `api.Client` and returns findings; `internal/cli` prints them. A finding has a severity (`ok`, `info`, `warn`, `fail`), a check id, a title, detail, and a hint (the next action). Checks:

1. Controller: endpoint and source, core version, more than one reachable controller.
2. Runtime config: `direct` mode (warn), `allow-lan` on (warn), `log-level: debug` (warn), TUN off together with no system proxy (fail, traffic bypasses the core).
3. System proxy: macOS `scutil --proxy`, Linux proxy environment variables; whether they point at the mixed port.
4. Egress: an HTTP request through the mixed port to the test URL, with latency.
5. DNS: `GET /dns/query` for the test host through the core.
6. Groups: from `/proxies` history, groups whose selected leaf node last failed (warn) and groups where every tested node failed (fail). `--probe` runs fresh group delay tests with bounded concurrency.
7. Providers: expired subscription (fail), expiry within 7 days or usage above 90 percent (warn), an HTTP provider not updated for 7 days (warn), a provider with no nodes (fail).
8. Routing: share of current connections that reached the final `MATCH` rule and the top hosts there, as hints for new rules; top hosts by traffic.
9. Logs: capture `--logs` (default 10s, 0 skips) at `--level` (default debug, because mihomo logs per-connection routing at debug and the bundle should keep it); count by level, group warning and error lines by pattern with addresses and numbers masked, list the top patterns.
10. Clash Verge Rev: app directory, service mode or not, current profile name from `profiles.yaml`, recent ERROR and WARN lines in `logs/latest.log` and the service logs grouped by pattern.
11. Conflicts: other Clash clients running at the same time (ClashX, ClashX Meta, another mihomo).

`--out DIR` writes `report.md`, `report.json`, `logs.ndjson`, `connections.json`, and `runtime-config.json`. It never copies profile files, subscription URLs, or secrets.

## Verification

Unit tests use `httptest` controllers and injected discovery. A local check runs read-only commands (`discover`, `status`, `logs --for`, `providers`, `rules`, `doctor`) against the real Clash Verge Rev core on the development Mac. State-changing commands are tested only against a mock controller.
